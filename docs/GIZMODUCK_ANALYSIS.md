# Gizmoduck для Nintendo Switch — технический анализ

Документ описывает текущую Switch-обёртку и её границы. Игровые данные не
хранятся в репозитории, поэтому факты о содержимом PCK относятся только к
локально проверенным пользовательским копиям и должны перепроверяться после
каждого обновления Gizmoduck.

## Краткий статус

| Область | Состояние |
| --- | --- |
| Целевая версия метаданных NRO | `1.1.16` (`Makefile`) |
| Вход для подготовки | Официальный Windows ZIP или распакованный `Gizmoduck.exe` |
| Ресурсы игры в Git | Не публикуются |
| Движок контрольной 1.1.2-сборки | Godot `4.7.2` Stable |
| Runtime Switch | Официальный Godot Android ARM64 runtime, загружается локально |
| Реальная Switch | Не заменяется локальными тестами; требуется отдельный hardware smoke test |

## Получение данных игры

`scripts/prepare_port.py` принимает официальный ZIP предпочтительно. Он находит
ровно один файл с именем `Gizmoduck.exe` (в том числе внутри вложенной папки),
извлекает его только в `.work/.../source/` и передаёт последующим этапам.
Уже распакованный EXE также поддерживается.

`scripts/prepare_game.py` ожидает встроенный Godot PCK: находит trailer `GDPC`,
проверяет формат PCK `4`, запрещает зашифрованный каталог и зашифрованные записи,
проверяет MD5 каждой извлекаемой записи и не допускает пути за пределы папки
вывода. `scripts/make_pck.py` копирует тот же встроенный пакет как единый
`game.pck` без перекодирования.

Если будущий релиз использует шифрование, другой формат PCK или несколько
`Gizmoduck.exe`, сценарий завершится ошибкой вместо создания неполного пакета.
Это ожидаемая защита, а не обход защиты игры.

## Что было установлено для исходной 1.1.2

Это историческая контрольная точка, а не утверждение о каждой новой версии:

| Свойство | Результат |
| --- | --- |
| PCK | format `4`, встроен в Windows и Linux исполняемые файлы |
| Флаг PCK | `0x2` (`PACK_REL_FILEBASE`), каталог не зашифрован |
| Файлы | 3 469 |
| Скрипты | 353 скомпилированных `.gdc`, исходных `.gd` нет |
| Native extensions / Mono | Не обнаружены |
| `project.binary` | SHA-256 `4EAB86E1D252CEB146E3A75487DE3673CE609079AEED0EB4F0996364AE4EFD9E` |

У проекта были renderer `gl_compatibility`, InputMap для gamepad и autoload для
Storage, AudioManager, CrtFilter, Leaderboard и UpdateChecker. Состав и хеши
не следует переносить на 1.1.16 или будущие версии без повторной локальной
проверки.

## Раскладка на SD-карте и приоритет данных

Обёртка ищет `libgodot_android.so`, `libc++_shared.so` и игровые данные рядом
с NRO. Достаточно **одного** источника игровых данных: `assets/project.binary`
либо непустого `game.pck`. Если есть `game.pck`, он передаётся Godot параметром
`--main-pack`; это сокращает число обращений к файловой системе при загрузке.

Полная подготовка сейчас кладёт оба варианта: распакованный `assets/` нужен для
Switch-специфических правок `project.binary` и `crt.gdshader`, а `game.pck`
оставляет исходный полный пакет. Не удаляйте `assets/` из созданного пакета,
пока не проверена конкретная версия игры на Switch: PCK допускается обёрткой,
но не содержит Switch-переопределений из распакованной папки.

Каталог `save/` является отдельным пользовательским хранилищем и не должен
заменяться при обновлении. В нём же создаются `cache/` и `shader_cache/`.

## Работа обёртки

- NRO содержит NACP с названием, авторами и JPEG-иконкой, извлечённой локально
  из пользовательского EXE; иконка не включается в исходный репозиторий.
- Runtime загружается как ARM64 Android-библиотека через собственный ELF-loader.
  Обёртка предоставляет bionic/newlib filesystem, потоки, сокеты, JNI,
  AssetManager, EGL/GLES через switch-mesa, OpenSL ES audio и HID.
- Экран выбирается автоматически: `1280×720` в портативном режиме и
  `1920×1080` в docked. Конфигурация позволяет переопределить размеры только
  для диагностики.
- Ввод Switch передаётся как Godot joypad. Сенсорные события намеренно не
  отправляются: Android-оверлей, появляющийся после касания, не соответствует
  физическим контроллерам Switch и занимает боковые поля.
- При старте и длительных кадрах используется CPU boost. `boot_stats.txt`
  фиксирует фазы загрузки и зависания; `gizmoduck_debug.log` предназначен для
  диагностики аварий.
- При выходе main-поток сначала ждёт игровой поток и только затем вызывает
  уничтожение Godot, чтобы следующий запуск из hbmenu не наследовал активный
  runtime.

## Изображение и CRT

Switch-пакет добавляет в `project.binary` режим stretch `expand`, сохраняя
исходный пиксельный аспект и не растягивая сцену по горизонтали. Чёрные поля
при этом ожидаемы.

Полноэкранный CRT-шейдер Gizmoduck использует `hint_screen_texture`. На
Switch Mesa он может читать незавершённый backbuffer и перекрывать кадр белыми
или чёрными полосами. Поэтому `package_sd.py` заменяет Switch-копию шейдера на
безопасный no-op. Возврат полноценного CRT требует отдельного корректного
multi-pass copy path, а не только правки файла шейдера.

## Проверка и границы подтверждения

Локально проверяются структура PCK, подготовка ZIP/EXE, SD-раскладка, AArch64
runtime и тесты Python. На данный момент автоматические тесты не доказывают
работу графики, звука, ввода, сна/пробуждения, сети, повторного запуска и
сохранений на консоли.

Для аппаратной проверки используйте [HARDWARE_SMOKE_TEST.md](HARDWARE_SMOKE_TEST.md)
и прикладывайте `gizmoduck_debug.log` вместе с `boot_stats.txt`. Запуск должен
выполняться через title override, а не Album/applet, иначе может не хватить
непрерывной памяти для Godot runtime.
