# Проверка на Nintendo Switch

Этот сценарий выполняется после копирования собранного пакета на SD-карту или
загрузки NRO через nxlink. Он отделяет уже выполненные локальные проверки от
того, что может подтвердить только настоящая Switch.

## Подготовка

1. Соберите обычную диагностическую версию:

   ```sh
   make clean && make DEBUG=1
   ```

2. Соберите SD-layout на Windows:

   ```powershell
   python scripts/package_sd.py `
     --nro gizmoduck.nro `
     --runtime .work/runtime `
     --game .work/extracted-win `
     --output release/switch/gizmoduck `
     --replace
   python scripts/verify_sd_layout.py release/switch/gizmoduck
   ```

3. Скопируйте содержимое `release/switch/gizmoduck` на SD-карту, сохранив
   точный путь `/switch/gizmoduck`. Homebrew Menu должен видеть
   `/switch/gizmoduck/gizmoduck.nro`.

4. Для максимального объёма непрерывной памяти запускайте Homebrew Menu через
   title override (удерживать `R` при старте обычной игры). Это особенно важно
   для Godot 4: резерв загрузчика занимает 88 MiB, а `libgodot_android.so`
   содержит большой сегмент данных и кода.

## Первый запуск и логи

Запустите приложение. При USB-подключении можно отправить NRO командой:

```powershell
& C:\devkitPro\tools\bin\nxlink.exe -a <IP_SWITCH> gizmoduck.nro
```

Сохраните весь вывод nxlink в текстовый файл. В диагностической сборке он
должен включать строки о загрузке `libgodot_android.so`, инициализации Godot и
старте основного цикла. Отсутствие изображения, внезапный выход в Homebrew Menu
или ошибка загрузки `.so` — достаточный повод приложить лог целиком.

## Чек-лист

| Проверка | Что сделать | Ожидаемый результат |
| --- | --- | --- |
| Загрузка | Открыть приложение из Homebrew Menu | Меню Gizmoduck появляется без чёрного экрана и без возврата в меню. |
| Изображение | Проверить меню и первый игровой экран | Корректные пропорции 4:3/пиксельная картинка, нет постоянных артефактов или мерцания. |
| Основные кнопки | В меню и игре проверить D-pad/стик, A, B, X, Y, L/R, ZL/ZR, Plus и Minus | Игра использует свой исходный InputMap; все требуемые действия доступны без клавиатуры. |
| Joy-Con | Проверить пристёгнутые Joy-Con, раздельный Joy-Con и Pro Controller | Ввод не пропадает после подключения/отключения; одиночный Joy-Con корректно поворачивается. |
| Звук | Меню, обычный уровень, пауза и босс | Музыка и эффекты есть, без треска, ускорения или заметной рассинхронизации. |
| Прохождение | Начать новую игру, пройти каждый уровень, босса и финал | Нет блокирующих ошибок, прогресс и финальные титры достигаются. |
| Сохранение | Создать прогресс, полностью выйти, открыть игру снова | Прогресс восстановлен из `/switch/gizmoduck/save`. |
| Сон/фокус | Усыпить и разбудить Switch, вернуться в Homebrew Menu и снова открыть игру | Нет зависания, звук/изображение/ввод восстанавливаются. |
| Режимы консоли | Проверить портативный и docked режимы | Нет краша или испорченного масштаба после смены режима. |
| Сеть | При доступной сети открыть таблицу лидеров/проверку обновлений | При недоступности сети игра корректно сообщает ошибку и не зависает. |

## Что приложить к отчёту

* Версию NRO и SHA-256 файла.
* Способ запуска: SD-карта или nxlink, title override использовался или нет.
* Версию Atmosphère/HOS и модель консоли.
* Полный вывод nxlink либо фото/видео экрана ошибки.
* Файл `/switch/gizmoduck/boot_stats.txt`: он содержит метки времени загрузки
  библиотек, инициализации Godot, первых кадров и длинных зависаний.
* Для каждого сбоя — действие, после которого он возник, и повторяется ли он.

Не удаляйте каталог `save` до сохранения его копии: он нужен для разбора
ошибок сохранений.
