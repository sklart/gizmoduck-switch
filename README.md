# Gizmoduck для Nintendo Switch

> Неофициальный homebrew-порт. Игра и все права на неё принадлежат их владельцам.
> Официальная страница игры: [Sova Games — Gizmoduck](https://sova-games.ru/en/games/gizmoduck/).

Этот репозиторий содержит только исходный код Switch-обёртки и инструменты
сборки. Игровой `.exe`, PCK, ассеты, оригинальная иконка, runtime, шрифт,
библиотеки и готовые архивы намеренно не публикуются.

---

## Для игроков

### Что потребуется

- Nintendo Switch с настроенным homebrew;
- легально полученный официальный ZIP Gizmoduck для Windows;
- готовая папка порта, собранная владельцем игры по инструкции ниже.

> [!IMPORTANT]
> Папка `assets/` обязательна и при наличии `game.pck`: обёртка проверяет
> `assets/project.binary` перед запуском, а PCK Godot подключает как основной
> пакет игры. Не удаляйте её.

### Установка на SD-карту

Скопируйте **содержимое** готовой папки `release/switch/gizmoduck/` в:

```text
sdmc:/switch/gizmoduck/
```

В конечной папке должны быть следующие элементы:

```text
gizmoduck.nro
libc++_shared.so
libgodot_android.so
game.pck
assets/project.binary
android_root/
save/
```

При обновлении заменяйте файлы порта, но сохраняйте `save/`, если хотите
оставить прогресс и настройки.

### Запуск

Запускайте через **title override**: удерживайте `R`, откройте обычную
установленную игру, затем в hbmenu выберите Gizmoduck. Режим Album/applet не
даёт приложению достаточно памяти.

### Управление

Порт передаёт A/B/X/Y, L/R, ZL/ZR, D-pad, оба стика, `+` (Start) и `-` (Back)
как стандартный контроллер Godot. Назначение действий определяется настройками
самой Gizmoduck. Один отсоединённый Joy-Con автоматически поворачивается; для
левого его ориентацию задаёт `joycon_turn`.

### Настройки порта: `config.txt`

После первого запуска рядом с NRO создаётся `config.txt`. Формат строки:
`ключ значение`; пустые строки и строки с `#` в начале игнорируются.

| Ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `screen_width`, `screen_height` | `-1` | Автоматический размер экрана; менять только для диагностики. |
| `boost` | `0` | `0` — частота CPU повышается на загрузках и долгих кадрах; `1` — повышенный режим постоянно. |
| `split_joycons` | `0` | `1` делает каждую половину Joy-Con отдельным игроком. |
| `joycon_turn` | `3` | Поворот левого одиночного Joy-Con на 0–3 четверти по часовой стрелке. |
| `controller_menu` | `0` | От `1` до `4` показывает системное распределение контроллеров при старте. |

`data_root` и `save_root` предназначены для диагностики нестандартной установки;
не меняйте их без необходимости.

### Если игра не запускается

`make` создаёт диагностическую сборку и журнал
`sdmc:/switch/gizmoduck/gizmoduck_debug.log`. После аварийного запуска
сохраните его вместе с `boot_stats.txt`. Параметр `VERBOSE_IO=1` включает очень
подробный журнал операций с файлами и заметно замедляет игру — используйте его
только для диагностики.

Чёрные боковые поля нормальны: игра сохраняет исходные пропорции кадра.
Сенсорное управление Android намеренно отключено — для Switch используются
физические контроллеры. CRT-фильтры зависят от версии игры и драйвера Mesa;
если изображение полностью белое или чёрное, выключите фильтр в настройках
игры.

## Для разработчиков

### Правовые границы и содержимое репозитория

В Git не добавляются игровые данные, извлечённая иконка, PCK, Android runtime,
шрифты и готовые двоичные файлы. Скрипты получают их локально из предоставленного
пользователем оригинального `.exe` и официальных источников. Поэтому публичный
репозиторий можно клонировать, но без законно полученной копии игры он не является
готовой к запуску сборкой.

Обёртка распространяется по MIT. Общий loader основан на MIT-совместимой работе
delsonazevedo и fgsfds/NaGaa95/elliencode; игровые ресурсы и патчи чужих
проектов не переносились. Noto Sans CJK используется по SIL Open Font License
1.1.

### Быстрая подготовка локального порта

В devkitPro MSYS2 установите devkitA64, `libnx`, `switch-mesa`,
`switch-libdrm_nouveau`, `switch-zlib`, Python, PowerShell и `make`, затем
выполните:

```sh
python scripts/prepare_port.py "D:/Gizmoduck-1.1.16-win64.zip" --replace
```

Сценарий находит `Gizmoduck.exe` внутри указанного официального ZIP, извлекает
его во временную папку, а затем получает из него PCK, распакованные ассеты и
JPEG-иконку. Также он
получает официальный Godot Android runtime и Noto Sans CJK, собирает NRO,
формирует `release/switch/gizmoduck/` и проверяет итоговую раскладку.

Полезные параметры:

| Параметр | Назначение |
| --- | --- |
| `--work-dir ПАПКА` | Расположение временных извлечённых файлов. |
| `--output ПАПКА` | Целевая папка SD-раскладки. |
| `--replace` | Удаляет только указанную сгенерированную рабочую и выходную папки перед подготовкой. |
| `--aar ФАЙЛ`, `--runtime-sha256 ХЕШ` | Использовать заранее скачанный Godot runtime и при необходимости проверить его хеш. |
| `--cjk-font ФАЙЛ`, `--font-url URL` | Использовать локальный CJK-шрифт или иной URL. |
| `--skip-build` | Не выполнять `make`; подходит, когда NRO уже собран. |

### Ручная последовательность

Для новой версии игры запустите `prepare_port.py` с её новым официальным ZIP.
Сценарий также принимает уже распакованный `Gizmoduck.exe`, но ZIP предпочтителен:
это исходный неизменённый файл релиза. При
необходимости этапы можно выполнить отдельно: `prepare_game.py`, `make_pck.py`,
`prepare_runtime.py`, `extract_original_icon.ps1`, `make`, `package_sd.py` и
`verify_sd_layout.py`.

Не добавляйте результаты этих команд в Git: `.work/`, `assets/`, `release/`,
PCK, runtime и игровые файлы защищены `.gitignore`.

### Проверки

```sh
make
make clean && make DEBUG=1
python -m unittest discover -s tests -v
python scripts/verify_sd_layout.py release/switch/gizmoduck
```

Локальная devkitA64-сборка подтверждает компиляцию NRO. Графику, звук, ввод,
lifecycle и прохождение необходимо проверять на реальной Switch; см. `docs/`.
